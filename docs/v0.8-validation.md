# ZeroSound v0.8 validation record

This record maps the implementation to the acceptance contract in
[`v0.8-room-rewrite-plan.md`](v0.8-room-rewrite-plan.md). It distinguishes checks completed on this
Mac from physical office checks that require the other Macs.

## Architecture and product checks completed

- The old role selector, sidebar, session/device screens, monolithic optional-field message, and
  role-shaped transport/controller types were deleted rather than adapted.
- The Foundation-only room domain owns stable IDs, membership transitions, authoritative snapshots,
  source transitions, coordinator terms, room revisions, deterministic succession, and the
  eight-member capacity.
- Control traffic is expressed as typed commands and events. Audio packets carry source identity and
  stream generation. Receivers and the coordinator independently reject stale audio.
- Bonjour advertises passive room descriptors through `_zerosound-room._udp`. Joining uses a stable
  installation member ID, so reconnect replaces rather than duplicates a member.
- Coordinator and audio-source responsibilities are separate. A coordinator change retains the room
  and roster, increments the term, fences the previous timeline, and leaves audio idle for a clean
  restart.
- The window has one discovery/room flow, centered one-to-eight-member rows, an elevated source,
  one stable action bar, live level, room rename, calm aggregate health, and a diagnostics inspector.
- The menu bar provides one-click visible-room join/create while outside and play/stop/leave/open
  controls while inside. These actions were exercised with the main window closed.
- Source level and health telemetry are coalesced to at most four roster publications per second.
  The Core Audio callback still performs no networking, logging, allocation, or UI work.
- Sleep/wake and process activity remain process-owned. A solo room is restored after wake; a member
  first reconnects to a visible replacement coordinator when one exists.
- The app icon, v0.8 version metadata, local-network description, and v0.8 Bonjour service are present
  in the packaged app.
- Diagnostics retain both current and worst round-trip latency for every member, including across a
  reconnect, and include both values in the copyable technical report.
- Bonjour preserves both control and audio protocol versions. Incompatible rooms remain visible but
  are clearly marked **Update required** and cannot be joined accidentally.

## Automated evidence

- `swift format lint --recursive Sources Tests Package.swift`: clean.
- `swift test`: 40 deterministic and integration tests pass.
- `swift test --sanitize=thread`: 40 tests pass with Thread Sanitizer.
- `swift test --sanitize=address`: 40 tests pass with Address Sanitizer.
- Real loopback UDP tests join a room and exercise an eight-member roster, a non-coordinator source,
  source transfer, stale packet rejection, and coordinator exit.
- The in-process fault harness uses an injected clock and covers loss, duplication, reordering,
  reconnect identity, transfer with packets in flight, and election.
- The universal archive contains both `arm64` and `x86_64`; the app and extracted archive pass strict
  code-signature verification and the archive passes decompression validation.

## Local packaged-app evidence

- Create Room completed in one app click after launch.
- Real 48 kHz system-audio capture and local delayed playback started successfully.
- Diagnostics during playback reported a 260–280 ms queue, 83.5 ms output latency, zero capture
  drops, zero concealed packets, zero underruns, and zero resynchronizations.
- Packetization measured approximately 200 packets/second, matching 5 ms packets.
- Removing an accidental per-packet main-actor publication reduced release streaming CPU from about
  100% to roughly 9–13% of one core. Physical footprint while streaming was about 48–70 MB in the
  sampling report.
- The main window, live source view, diagnostics sheet, and menu-bar remote were visually inspected
  in dark mode. Controls expose explicit accessibility labels; level animation disables itself when
  Reduce Motion is enabled.
- Closing the window left the room, audio, and menu controls active. Menu-bar Stop audio converged
  the source state to idle; Play from this Mac restarted it; Open Room reopened the main window; and
  Leave Room returned to discovery.

## Physical checks still required before calling the office rollout proven

These cannot be honestly simulated by one Mac and are the remaining release-candidate checks:

Follow [`office-validation-runbook.md`](office-validation-runbook.md) so every run uses the same
actions, pass criteria, and diagnostic evidence.

1. AirDrop the archive to at least one different Mac and confirm the documented Control-click Open
   flow for the current ad-hoc signature.
2. Run real two-, five-, and eight-Mac rooms on mixed hardware, including a non-coordinator source and
   coordinator departure during live playback.
3. Run the multi-hour congested-Wi-Fi soak and sleep/wake/interface/output-device matrix.
4. Check the two-, five-, and eight-Mac visual arrangements in light mode, dark mode, VoiceOver, full
   keyboard access, and Reduce Motion on physical displays.

The archive is a release candidate, not notarized distribution. A paid Apple Developer Program
Developer ID Application certificate remains necessary for a normal double-click install on a
friend's Mac.
