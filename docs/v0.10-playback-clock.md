# ZeroSound v0.10 Playback Clock

## Invariants

ZeroSound controls playback on every room member, including the audio-source Mac. The Core Audio
process tap mutes the original system output; captured audio is replayed through the same renderer
and room presentation timeline everywhere.

The synchronized pipeline maintains these invariants:

1. Network clock evidence may refine the room-clock model but may never jump an active timeline.
2. Clock offset and clock skew are separate quantities and are estimated together.
3. Playback health is based on the hardware playhead, not merely packet arrival or queued duration.
4. Small phase errors are removed continuously with bounded varispeed correction.
5. A sustained large phase discontinuity reuses already-buffered future audio for a controlled
   re-anchor instead of waiting for a new 300 ms safety buffer.
6. Health severity uses a rolling ten-second continuity window; lifetime counters remain available
   for investigation but cannot leave a healthy room permanently degraded.

## Clock discipline

Each receiver exchanges NTP-style four-timestamp pings with the coordinator. `ClockEstimator`
retains a bounded sample history, selects a low-latency candidate set, and fits an affine mapping:

```text
coordinator time = reference coordinator time
                 + (local time - reference local time) × clock rate
```

The estimator needs four samples before exposing a mapping. High-latency samples do not enter the
fit. Rate is bounded to realistic oscillator error, and new phase evidence is slewed by at most
250 microseconds per ping so sample selection cannot produce a presentation-time step.

## Playback phase loop

The first frame of every playback generation has an absolute local presentation timestamp.
`AVAudioPlayerNode.lastRenderTime`, `playerTime(forNodeTime:)`, and the measured output presentation
latency identify when the current player sample will reach the output device. `PlaybackTimeline`
compares that actual time with the intended room time for the same sample.

`PlaybackPhaseController` filters the measured phase error. Positive error means the speaker is
late and increases the varispeed rate; negative error means it is early and reduces the rate. The
correction is bounded to ±2,500 ppm and decays to unity inside a 0.35 ms deadband.

A phase error above 45 ms must persist for 1.5 seconds before re-anchoring. The renderer retains the
small set of already-scheduled PCM batches and restarts from a batch at least 120 ms in the future,
with a sample-domain fade-in. If the queue is too shallow, it falls back to normal future-packet
recovery.

## Diagnostics

Each member reports filtered phase error, current playback correction, output latency, total event
counters, rolling ten-second counters, and phase-resynchronization count. Room severity responds to
current phase and recent continuity rather than cumulative historical packet loss.
